# 미션 9-1 증빙 상태

2026-10-01 기준. 이 폴더는 구현 및 로컬 QA 자료이며, Amplitude·GA4 실제 수신 증빙을 대신하지 않는다.

## 완료한 항목

- 지표 5개, 이벤트 10개, 사용자·유입 속성 및 16개 QA 시나리오 정의
- 분석 코드 구현, 구글 신규 계정 응답 구분과 OpenAPI 문서 반영
- 새 분석 단위 테스트 13개 통과. analytics-unit-results.json 참조
- 프로덕션 빌드 통과. 번들 크기 경고가 있음
- 린트 실행 완료. 기존 컴포넌트의 Fast Refresh·effect 관련 경고 6개 유지
- 로컬 브라우저: UTM 방문, 가입 CTA, 이메일 가입, 후보 작성·저장, 비교 결과 0개 표시, 직접 보유 의류 추가, 화면상 유사 의류 1개, 샀다 결정 기록 확인
- 구매로 자동 생성된 Own은 own_created로 중복 기록되지 않음
- 3개 채널의 AI 작성 홍보 문구와 UTM 링크 준비. 실제 게시하지 않음

## 증빙 파일 해석

- local-comparison.png: 임시 DB에서 보유 의류 1개가 표시된 화면
- local-events-before-redirect-fix.json: 해당 브라우저에서 실제 기록된 QA 이벤트 원본. 운영 데이터가 아니다. 가입 직후 로그인 화면 중간 상태가 추가 page_viewed로 발생한 수정 전 샘플을 그대로 보존했다. 이후 인증된 /login을 제외하도록 수정했으며, 수정 후 페이지 분류는 단위 테스트로 검증했다. 수정 후 브라우저 재검증은 미완료다.
- analytics-unit-results.json: 최종 분석 모듈·전송 어댑터 단위 테스트 결과
- test-results.json: 최종 전체 테스트 재실행 원본. 104개 중 98개 통과, 6개가 read ECONNRESET으로 실패했다. 이전 실행에서는 100개 전체 통과했으나 최종 상태의 전체 통과를 주장하지 않는다. 샌드박스 밖 실행과 forks 실행에서도 연결 오류가 재현되어 원인은 아직 확정하지 못했다.
- baseline-test-results.json: 변경 전 HEAD 코드를 별도 임시 폴더에 펼쳐 동일한 설치 의존성으로 실행한 비교 결과. 91개 중 90개 통과, 1개가 동일한 read ECONNRESET으로 실패했다. 연결 오류가 변경 전 소스에서도 재현됨을 확인했으며, 이번 작업에서 기존 테스트를 완화하거나 삭제하지 않았다.

## 남은 확인

- 저장 실패 시 action_failed의 브라우저 실제 발생 확인
- 보유 등록 후 상세 재진입 시 comparison_viewed 값 확인
- 안 샀다 결정의 브라우저 실제 발생 확인
- 수정 후 신규 가입 리다이렉트, 로그아웃·다른 계정 로그인 재검증
- 전체 테스트의 간헐적 ECONNRESET 원인 확인 및 안정적 통과
- Amplitude·GA4·GTM 계정 생성, 태그 설정, 실제 수신 확인
- 운영 적용 후 데이터 수집, 3개 채널 게시 및 게시 증빙
